# Work Package — Dukascopy FX Cash Research Registry

- **ID:** `DTR-DFXC-WP-20260808-01`
- **Date:** 2026-08-08
- **Branch:** `agent/dukascopy-fx-cash-research-registry`
- **Implementation role:** `implementation_operations`
- **Status:** `IMPLEMENTATION_COMPLETE_ASSURANCE_PENDING`

## Objective

Create a durable, searchable research-memory framework for every study that uses the registered ten-pair Dukascopy FX dataset, using the canonical name **Dukascopy FX Cash**.

The framework must prevent methodology, falsification logic, negative findings, holdout state and branch-resident results from disappearing when a chat or working branch is no longer active.

## Scope

- preserve the existing permanent private cache and checksum contract;
- establish canonical human and machine dataset identity without breaking the legacy catalog key;
- define a normalized study/result object model;
- create a machine-readable master index plus generated human-readable index;
- freeze exact branch + commit + artifact paths for branch-resident evidence;
- enforce explicit pair universe, price basis, windows, controls, inference, holdout and evidence fields;
- retain negative results and prohibited rescue paths;
- seed the registry with recovered Quarters Theory and pivot-level research;
- create a migration queue for older Dukascopy FX branches that still require evidence-based reconstruction;
- add CI-covered validation.

## Non-goals

- no raw market data moves into Git;
- no strategy parameters or scientific results are changed;
- no protected holdout is opened;
- no branch-resident historical result is reinterpreted as stronger evidence;
- no live-trading, Pine publication or deployment authority is created;
- no forced merger of unrelated strategy implementations.

## Acceptance criteria

1. Canonical name `Dukascopy FX Cash` and ID `dukascopy_fx_cash_m1_bid_ask_v1` are documented.
2. Legacy dataset key remains usable.
3. Registry index and per-study manifests/results are machine readable.
4. Each completed registered study freezes exact Git evidence.
5. Holdout exposure cannot be silently omitted.
6. Negative and rejected results are first-class dispositions.
7. Human `INDEX.md` is deterministically rendered from `index.json`.
8. CI tests fail on registry drift, unindexed study directories or invalid canonical pair/dataset identity.
9. Quarters and pivot studies can be found without knowing their historical branch names.
10. Historical migration candidates are explicit rather than guessed into the registry.
11. Preregistered studies may exist before a result, but completed studies cannot omit a result record.

## Assurance boundary

Implementation may prepare this candidate but may not certify it. Independent `governance_release_assurance` should review:

- compatibility with the existing cache/data contract;
- whether the registry could accidentally relabel old evidence;
- validator coverage;
- holdout semantics;
- recovered-study fidelity;
- whether future research completion can bypass the registry.

No merge to `main` should be treated as assured until that review passes.
